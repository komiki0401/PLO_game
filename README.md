# POKER

ページを開いた直後は「ホールデム・ノンリミット」を選択します。卓の人数・スタックなどの保存設定は維持し、その場で他のゲームへ切り替えられます。トップ画面は、手札2枚の「ホールデム・ノンリミット」と「オマハ」を区切って表示します。オマハ内では「PLO4・プリフロップ」「PLO5・Wボードボムポット」を選べます。保存するゲーム種別や既存記録の形式は変更しません。

## 友達とのオンライン対戦

Cloudflare Workers / SQLite Durable Objectsによる招待制・2〜6人対戦を追加しています。全3ゲームに対応し、伏せ札を分けて配信、再接続、ホスト引き継ぎ、45秒の手番期限をサーバーで管理します。CPU戦とは別の画面・チップ管理です。

公開にはCloudflareの無料アカウントで対戦サーバーをデプロイし、画面側へ公開URLを設定する初回作業が必要です。未設定の公開画面は「準備中」と表示します。[起動・検証・公開の手順](docs/ONLINE_PLAY.md)を参照してください。

## ノンリミット・テキサスホールデム

トップ画面で「ホールデム・ノンリミット」を選択できます。手札2枚・共通ボード1組、SB/BB方式でプリフロップから始まり、フロップ3枚・ターン1枚・リバー1枚を公開します。各公開前に1枚バーンします。手札とボードの計7枚から自由に最強の5枚を選び、手札を0枚・1枚・2枚のどれでも使えます。ポット額の制限はなく、残りスタック全額までレイズできます。最低ベット・レイズ、ショートオールイン、サイドポット・同点分配も検証します。通常の合計ベット額は既存と同じ100単位です。

ボードは分割せず各ポットを勝者に全額分配します。ダブルボードのSCOOPとしては集計・演出しません。NPCの個性、音声、履歴・リプレイ、スコア保存に対応し、記録にはNLHを表示します。既存PLOのルールと保存キー・過去の記録は維持します。

プレイチップ専用、5カード PLO・ダブルボード・ボムポット。React + TypeScript + Vite。1人対CPU、2〜6人卓に対応します。換金・入出金・賞金はありません。

トップ画面のゲーム選択から、従来の **PLO5・ボムポット** と **PLO4・プリフロップ** を選べます。共通の設定欄で人数・スタック・難易度を選び「ゲームを始める」で開始します。

## PLO4・プリフロップ

- 手札4枚、ボード未公開のプリフロップから開始。アンティはなく、設定欄のビッグブラインド（BB）と、その半分を切り捨てたスモールブラインド（SB、最低1）を使用します。
- 3人以上ではボタン左にSB、その左にBB。プリフロップはBB左から、フロップ以降はボタン左から行動します。2人卓はボタンがSBで、プリフロップは先、フロップ以降は後に行動します。BBにはチェック／レイズの選択権があります。
- プリフロップ終了後に各ボードへフロップ3枚、続いてターン1枚・リバー1枚を公開。両ボードで同じベッティングラウンドを共有します。
- シングルボードで、各ポットは対象の勝者へ全額分配します。ホール2枚＋対象ボード3枚、ポットリミット、サイドポット、奇数チップ、音声、演出、CPU、履歴・リプレイは既存モードと共通です。全員フォールドならボードを開かず精算します。ブラインドでのショートオールインも処理します。
- 設定と新しいスコアにゲーム種別を保存します。既存の `plo-scores-v1` の記録は削除・移行せず、種別のない過去の記録はPLO5として表示します。

```sh

```


Windowsでは既存の `C:\Users\fabri\source\PLO_game` チェックアウトを使います。開発サーバーのプロセスは新しい環境で再起動してください。秘密鍵、APIキー、DB、外部サービスは不要です。

クラウド環境で再開する場合は、[クラウド開発の再開手順](docs/CLOUD_DEVELOPMENT.md)を参照してください。`.nvmrc` にNode.js 24を指定しています。Windowsの作業パスや生成物を引き継ぐ必要はありません。

## ルール

- 同一52枚デッキ、ホール5枚、ボード2組。アンティ後にフロップ2組を公開し、プリフロップのベットはありません。バーンカードは使用しません。
- 各ボードの役は必ずホール2枚＋そのボード3枚。ハイのみ。A2345は5ハイのストレート。
- 最低ベット＝アンティ。レイズ上限は現在の最高ベット＋現在のポット＋コール額（そのストリートの合計ベット額として入力）。スタックを上限とします。
- 最低レイズ幅は直前のフルベット／レイズ幅。ショートオールインは幅を更新しません。前回のアクション以後に直面する増額がフルレイズ幅に達すればレイズ権を再開します。
- チェック可能時はFoldを表示しません。コール不能な端数スタックはショートコールのオールイン。対戦相手全員がオールインの場合、未コール額へのコール／フォールドだけ行い、自動ランアウトします。
- 未コール分を返却し、累積拠出額でメイン／サイドポットを作成。フォールドの拠出分も含め、各ポットの有資格者だけを比較。
- 各ポットの奇数1チップはBOARD Aへ。同点で割り切れないチップはボタン左から時計回りに1枚ずつ。チップは整数。
- CPUのスタック0の席は次のハンドから休止。プレイヤーのスタックがハンド終了時に0なら、結果表示後にトップ画面へ戻ります。全CPUを倒した場合もトップ画面から新しいセッションを開始できます。

## 構成

- `src/game/cards.ts`: デッキ・カード・組み合わせ
- `src/game/evaluate.ts`: 5枚役判定とOmaha全候補比較、使用カードを返却
- `src/game/pots.ts`: メイン／サイドポットとボード別分配
- `src/game/betting.ts`: 合法アクション、ポットリミット、レイズ権
- `src/game/engine.ts`: 状態遷移。`act(state, action)` は新しい状態を返す
- `src/game/cpu.ts`: 公開情報だけを使うヒューリスティックCPU
- `src/App.tsx`: React画面・タイマー・音・履歴・統計

CPUはランアウトのMonte Carlo推定とポットオッズを使用し、EASYは参加判断が緩めです。難易度で推定の試行数を変えます。HARDは現在の両ボードのナッツをブロッカー込みで調べ、マルチウェイのスクープ率も考慮します。GTOソルバーではありません。

CPUには席ごとに固定の個性があります。AKIRAは広めに参加して大きく打つ攻撃型、LUNAは強い手を厳選しつつ安いコールには参加する堅実型、RENはプリフロップからベット・レイズして主導権を狙う積極加圧型、MIKAは安いレイズなら広くコールしてフロップで判断する参加型、SORAは役なしのベットやレイズも混ぜるブラフ混合型です。人数に応じてAKIRAから順に着席し、6人卓で全5タイプが登場します。

コールの判断は推定勝率と支払額に応じて変わり、安いベットへの過剰なフォールドを抑えます。プリフロップの広い参加は追加2BB以内・手持ちの8%以内などの条件付きで、大きなレイズやポストフロップまで無条件には追いません。ブラフは人数が少ないほど増え、大きな反撃やスタックに対して重すぎる額には抑えます。ベット額にも幅を持たせ、強い手とブラフを額だけで断定できないようにしています。

両ゲーム共通で、難易度はシミュレーション精度（EASY 8回、NORMAL 20回、HARD 48回）などに影響し、個性は参加基準・レイズ頻度・ブラフ頻度・ベット額に影響します。相手の伏せ札や実際の山札は参照しません。トップ画面とルール内の「CPUの個性を見る」で傾向を確認でき、席の顔アイコンにも短い表示があります。既存の設定・スコアの保存形式やキーは変更しません。

履歴は現在のテーブルの直近30ハンドをメモリ保存（一覧は直近8件）。「リプレイ」はスライダーで各アクション時点の状態を再表示します。伏せ札は当時の公開状態を維持し、終了時にショーダウンを確認できます。統計と設定はlocalStorageに保存されます。

オンライン拡張時はゲームモジュールをサーバー側で実行し、合法性を権威的に検証してください。伏せ札を含むState全体はクライアントに配信せず、各席用の公開ビューを生成する設計を想定しています。現在はローカルCPU戦専用です。シャッフルはプレイチップ用のMath.randomベースです。

## GitHub Pages

`.github/workflows/pages.yml` がmainへのpush時に依存関係の監査・ユニットテスト・ビルド・ブラウザテストを実行し、すべて通った場合だけデプロイします。監査でhigh以上の脆弱性が見つかった場合は公開を停止します。PRでは検証のみ実行します。Viteの相対baseによりリポジトリ配下で動作します。

初回のみGitHubリポジトリの **Settings → Pages → Build and deployment → Source → GitHub Actions** を選択してください。mainへpushし、Actionsの「Test and deploy to GitHub Pages」が成功すると公開されます。標準の公開先は `https://komiki0401.github.io/PLO_game/` です。URLの利用可能性はデプロイ完了後に確認してください。

公開後はスマホのブラウザから上記HTTPS URLを開けます。開発用PCの起動や同じWi-Fiへの接続は不要です。公開されるのはゲーム本体と同梱素材で、Supabaseには接続しません。スコア・統計・設定は引き続き各ブラウザのlocalStorageに保存し、送信しません。ローカルURLの既存記録は削除しませんが、公開URLや別端末には自動移行されません。同じ公開URL・同じブラウザの記録は更新後も維持します。フォントの取得時にはGoogle Fontsへ接続します。

## ショーダウン表示

BOARD A の勝利ハンド（ホール2枚＋ボード3枚）と勝者・役名を表示してから、BOARD B に進みます。選択中の5枚だけを明るくし、それ以外のホールカード・ボードカードはすべて暗く表示します。標準では各表示を2.6秒保持し、高速設定でも最低1.6秒は表示します。同点・サイドポットは各勝利ハンドを順番に表示します。すべての結果を表示した後にチップ獲得演出と次のハンド操作を表示し、結果カードやボード名からハンドを見直せます。

## SE と女性ボイス

「音声を有効にする」を押すとSEと日本語女性ボイスを再生します（ブラウザの自動再生制限により最初の操作が必要です）。設定でSE・ボイスを個別に切り替え、音量を調整できます。ミュートは現在の読み上げもすぐ停止します。

配札・チェック・チップ・フォールド・ボード公開・勝利・スクープにWeb AudioのSEを用意しています。ショーダウンはBOARD Aの役を読み上げてからBOARD Bへ進み、読み上げが長い場合は表示時間を延長します。役名の読み上げは各ボードで1回だけです。同点・サイドポット・結果の選び直し・リプレイでも繰り返しません。結果カードやボード名からハイライトを見直せます。非表示タブでは読み上げを止め、再生エラー時もゲームが進む設計です。

女性ボイスはKokoro `jf_alpha`の合成音声を役名18本とコール・レイズ・ベット・オールイン4本を事前生成したMP3です。OSの読み上げ音声に依存せず、プレイ中に外部TTSサービスへ通信しません。[音声クレジット](public/audio/voice/NOTICE.md)、ライセンス文書と生成テキスト・長さのmanifestを同梱しています。通常のビルドにはPythonやモデルは不要です。音声を作り直す場合だけ `scripts/generate_voice.py` を使用します。

コール・レイズ（初回はベット）も同じ女性ボイスで読み上げます。発声は順番に再生し、CPUは直前のアクションの読み上げが終わってから進みます。ミュートと新しいセッションの開始で待機中の音声も取り消します。

## チップの表示

通常のベット・レイズは、そのストリートの合計額を100単位で選びます。入力欄・スライダー・ポット割合ボタン・CPUに共通です。最低合法額は100単位に切り上げ、ポット上限は切り下げます。100単位で合法な額がない場合は、合法な全額オールイン以外のベット／レイズを表示しません。ブラインド・コール・全額オールインの端数は維持し、既存の残高・スコアを丸めたり削除したりしません。

各席の残りスタックを1,000・100・25・5・1の額面ごとのチップに分けて表示します。各山の「×」は保有枚数です。山は表示上最大8枚とし、大きな残高でも画面を埋めないようにしています。金額と枚数は省略せず、ベット・獲得時やリプレイ時も表示中の残高と一致します。ショーダウン演出中の未配分チップは先に残りスタックへ表示しません。

残高・ポット・ベット・獲得額の数字を拡大し、狭い画面や大きな金額でもカードと重ならない配置にしています。

## ロゴ・背景と手番の表示

丸い「D」チップはディーラー席の手札の横、テーブル内側に表示します。右側の席では手札の左、左側と上下の席では手札の右に配置します。中央のボタン表示はありません。次のハンドでは移動先を、リプレイでは当時の位置を表示し、ディーラーがフォールドしてもDは明るく表示します。

`public/branding/` に専用のロゴ画像とポーカーモチーフの背景画像を同梱しています。深いグリーンとゴールドで統一し、タイトル画面には「POKER」の透過PNGロゴを表示し、背景などの既存素材はWebPで配信します。

自分の手番では相手全員のホールカードを暗くし、自分のカード・座席・操作欄を強調して「あなたの番」を表示します。手番が終わると通常表示に戻ります。リプレイでは現在の手番強調を表示せず、ショーダウンでは従来どおり選択中の勝利ハンド5枚を強調します。

## トップ画面・スコア記録

最初はトップ画面を表示し、「今すぐプレイ」または設定欄の「ゲームを始める」から新しいセッションを開始します。トップ画面ではCPUは動きません。テーブルの「トップへ」やロゴからも戻れます。

プレイヤーのスタックが0でハンドが確定した場合、ショーダウンと獲得演出を完了してから、暗転と「You lose...」の文字演出を3秒間表示し、タイトル画面へ戻ります。端末の「視差効果を減らす」設定ではアニメーションを抑えます。未確定のオールインでは戻りません。全CPUを倒した場合も同じ流れです。

各ハンド終了時に、最終スコア（残りスタック）、最高到達スタック、初期スタックからの収支、ハンド数、スクープ数、テーブル設定、日時をlocalStorage `plo-scores-v1`へ保存します。セッションごとに同じ記録を更新し、最新50件を保持します。途中でトップへ戻る／設定で新しいテーブルを作ると、最後に確定したハンドまでを「中断」として記録します。再読み込み後もトップ画面で記録を見られます。進行中にページを閉じた場合も、最後の確定ハンドまでの記録が残ります。端末間の同期やゲーム途中の再開は行いません。

記録の日時は日本時間で表示します。保存が拒否された場合は画面にその旨を表示し、ゲームと現在の画面上の記録は継続します。

## コンパクト表示とオールイン

テーブル・自分の手札・ベット操作を画面の高さに合わせて配置し、スクロールせず操作できます。履歴や詳細結果はその下に配置しています。

オールイン時はプレイヤー名と投入額のカットイン、専用SE、女性ボイス「オールイン」を再生します。少なくとも1.6秒表示し、読み上げ終了後に次のアクションやショーダウンへ進みます。アンティでのオールインにも対応し、席にもALL-INを表示します。ポットリミットの上限を超えるオールインはできません。

スクープ時は両ボードの役表示・読み上げ終了後に、大きな「SCOOP!」、金色の光・チップ・紙吹雪、勝者名と獲得チップ数を2.8秒表示します。専用SEも再生します。演出は1ハンドにつき1回で、結果の再選択・リプレイでは繰り返しません。端末の「視差効果を減らす」設定では動きを抑えた表示になります。

各席に6種類のオリジナル人物ポートレートを固定表示します。従来の席マークは顔の横の小さなバッジとして残し、スタックが大きい場合も金額と重ならない配置にしています。画像は `public/characters/portraits.webp` に同梱し、プレイ中に外部画像サービスへ接続しません。
